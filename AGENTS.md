## О проекте

Позиционирование: «Андрей Семенов — ИИ-ассистенты для бизнеса».

## Технический стек

- **Backend:** Python 3.10+, Flask 3.0
- **База данных:** SQLite через Flask-SQLAlchemy
- **Авторизация:** Flask-Login
- **Формы и CSRF:** Flask-WTF + CSRFProtect
- **Шаблоны:** Jinja2
- **Стили:** чистый CSS, без Bootstrap
- **Шрифты:** Inter (основной текст) + JetBrains Mono (номера, метки, код)
- **RAG-чат:** генерация — GigaChat (модель `GigaChat-2`), поиск — FAISS
  + локальные эмбеддинги fastembed (`paraphrase-multilingual-MiniLM-L12-v2`,
  ONNX, ~120 МБ, данные не покидают сервер)

### Запуск

```bash
cd andrey-ai-lab
pip install -r requirements.txt
python app.py
```

Сайт: `http://127.0.0.1:5000/`  
Админ-панель: `http://127.0.0.1:5000/admin/`

Логин/пароль администратора задаются в `config.py`.

### v1.7 — локальные эмбеддинги, мелкие исправления запуска (08.11.2026)

- **Эмбеддинги переведены с GigaChat на локальный fastembed**: модель
  `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (ONNX,
  качается при первой сборке ~120 МБ). Причина: эмбеддинги GigaChat платные
  отдельно от токенов чат-моделей (402 Payment Required). Новый модуль
  `backend/embeddings.py` (`embed_texts`), используется в `app.py`
  (`embed_query`), `backend/build_index.py` и `backend/app.py`.
  GigaChat остался только для генерации ответов.
- **Модель чата по умолчанию — `GigaChat-2`**: старое имя `GigaChat` на
  api.giga.chat больше не существует (404 No such model). Меняется через
  `GIGACHAT_MODEL` в .env.
- **Баг с закрытым клиентом**: `with gigachat_client as giga:` закрывало
  httpx-клиент после первого запроса, второй запрос чата падал. Теперь
  вызов без контекстного менеджера (`app.py`, `backend/app.py`).
- **`config.py` сам загружает `.env`** (`load_dotenv()` в начале файла):
  раньше `Config` читался до `load_dotenv()` в `app.py` и приложение
  падало с «ADMIN_PASSWORD не задан» при запуске `python app.py`.
- **Пароль администратора синхронизируется из env при старте**: если
  `ADMIN_PASSWORD` в .env изменился, хэш в SQLite обновляется
  (`create_admin_user` в `app.py`). Раньше пароль применялся только при
  первом создании пользователя, смена в .env не имела эффекта.
- Пересобран RAG-индекс (`python -m backend.build_index`) — старый индекс
  был под чужие эмбеддинги и несовместим по размерности.
- Проверено локально: главная, чат (2 вопроса подряд), вход в `/admin/`

### Деплой на РФ-сервер: грабли и решения (08.11, вечер)

- **gunicorn не исполняет `if __name__ == '__main__'`** — на чистом сервере
  база SQLite не создавалась, `/admin/` и форма падали с 500 «unable to open
  database file». `scripts/deploy.sh` теперь сам делает `mkdir -p instance`
  и прогоняет `db.create_all()` + `create_admin_user()` (idempotent).
- **sudoers**: `systemctl` в Ubuntu 24.04 — `/usr/bin/systemctl` (не `/bin`),
  плюс флаги типа `--quiet` ломали точное совпадение. Рабочая строка:
  `deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl * andrey-ai-lab*`.
- **rsync не входит в минимальный Ubuntu** — `apt install rsync` иначе
  workflow падает с exit code 12.
- **DEPLOY_SSH_KEY храним в base64 одной строкой** (в workflow делается
  `base64 -d`) — многострочный ключ при копировании в секрет GitHub
  терял символы («error in libcrypto»).
- **DNS Timeweb**: записи удаляются/создаются заново (редактирования нет),
  NS-серверы (ns2/ns4) синхронизируются с задержкой — Let's Encrypt и
  GitHub Pages DNS-check могут падать, просто повторять спустя время.

## Как добавлять кейсы

Кейсы хранятся в Python-списке `CASES` в файле `app.py`. Каждый кейс — словарь с полями:

```python
{
    'slug': 'уникальный-идентификатор',
    'number': '06',
    'title': 'Название кейса',
    'short': 'Краткое описание для карточки',
    'tags': ['Tag1', 'Tag2'],
    'github': 'https://github.com/...',
    'image': 'case-slug.svg',
    'details': 'Подробное описание проекта',
}
```

### Добавление кейса по ссылке на GitHub

AI-ассистент может добавить кейс по ссылке на публичный репозиторий:

1. Пользователь присылает ссылку, например:
   `https://github.com/semandr72-eng/ai-hr--company-assistant`
2. Ассистент читает README и структуру репозитория
3. Составляет заголовок, краткое и подробное описание
4. Определяет технологии по коду (FastAPI, ChromaDB, LangChain и т.д.)
5. Добавляет новый словарь в `CASES` в `app.py`
6. Создаёт SVG-заглушку в `static/images/` или предлагает загрузить картинку
7. Проверяет, что страница `/cases/<slug>/` открывается
8. Sitemap обновляется автоматически

### Ограничения

- Работает только с публичными репозиториями
- Сложную бизнес-логику лучше объяснить парой фраз
- После изменений `app.py` нужно перезапустить приложение

## Важные замечания

- В production обязательно задать через переменные окружения: `SECRET_KEY`,
  `ADMIN_PASSWORD` (без него приложение не стартует), `GIGACHAT_CLIENT_ID` /
  `GIGACHAT_CLIENT_SECRET` или `GIGACHAT_CREDENTIALS`. Образец — `.env.example`.
- Логин и пароль администратора хранятся только в переменных окружения,
  в коде их быть не должно (репозиторий публичный).
- `instance/site.db` с заявками — только локально на сервере, в git не коммитить.
- База данных SQLite создаётся автоматически при первом запуске
- После изменений `app.py` и `config.py` приложение нужно перезапускать
